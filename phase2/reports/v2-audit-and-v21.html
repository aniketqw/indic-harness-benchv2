Indic Harness Bench · phase 2 · audit report · 18 Nov 2026

Auditing v2 and running the corrected v2.1 suite

The first full campaign (v2) was audited failure by failure. Two tasks had specification defects that marked correct answers wrong. We added a generic value glossary to the task notices without changing any data, rules or answers (v2.1), ran all 192 conditions again, and audited the new failures the same way. This report covers both campaigns.

GLM-5.3-Flash and Nemotron 3 Super · 16 tasks × 3 instruction languages × 2 workspace languages × 2 models · one run per condition

  • v2 had about 11 false failures. Task 14 (lab flags) never said whether to output test codes or test names. Task 06 (seed allocation) used undocumented cultivar names for varieties. A further 5–7 runs were partly affected by smaller cases.
  • The fix is generic and leaves the answer key unchanged. Every notice now ends with a glossary of the values the files write in more than one form, plus the exact codes required in the output. Each v2 notice is an exact prefix of its v2.1 notice.
  • The defective tasks recovered and the benchmark did not saturate. Task 14 went from 0 to 8 correct and task 06 from 2 to 10. Overall v2.1 is 76%, with clearly hard tasks (appointment rebooking 5/12, exam seating 7/12).
  • The main new finding is a Hindi-workspace penalty that v2 hid. In 96 matched pairs that differ only in the workspace language, 22 are correct only with English files and 6 only with Hindi files. In v2 this was 20 vs 20, because the defects mostly broke English-workspace runs.
  • Single conditions are noisy. On the two tasks that are byte-identical across versions, 7 of 24 conditions changed result between runs. Use aggregates, not individual cells.

What the v2 audit found

For every v2 output that was not perfect, we compared it cell by cell with the answer key. We also re-ran the reference solver under a literal reading of every value form the notice did not mention, and scored the output against those alternative keys. A failure counts as false when a faithful reading of the notice produces the model's answer.

The audit also confirmed that most v2 failures were genuine model errors:

  • 16 missing output files, almost all Nemotron runs that used the whole output budget;
  • 5 format errors, such as a wrong header or an extra column;
  • query text written in place of the query ID (task 08);
  • lower-case Roman numerals despite an explicit upper-case rule (task 16);
  • rule mistakes in otherwise valid files.

A case-insensitive rescoring changed only the Roman-numeral run.

The v2.1 change

Nothing in the data, rules, prompts, answers or budgets changed. authoring/core.py appends one section to every notice, built from the generator's own value tables:

  • a glossary listing every coded value that a workspace writes in more than one form;
  • an output-values line giving the exact codes required for any output column that holds coded values.

Example from task 14: results.csv, test: GLU = Glucose (fasting); HB = Hemoglobin; K = Potassium; CREAT = Creatinine. Then Output values: in out/result.csv, write test as one of these codes: GLU, HB, K, CREAT.

The build checks that each v2 notice is an exact prefix of its v2.1 notice. Tasks 07 and 08 had no multi-form values and are byte-identical. The rule ablations are unchanged: ignoring any single rule still scores below 100 on every task. The v2 task files and generator are preserved in phase2/archive/v2-final/.

Disclosure. This change was made after seeing v2 model outcomes. We limited it to a generic, mechanically generated clarification that adds no new rules or hints and applies the same way to every task. Both campaigns are reported: v2 as a preliminary run whose audit motivated v2.1, and v2.1 as the primary result.

    • GLM writes a file but gets more fields wrong: 15 partial outputs with Hindi files vs 6 with English.

Was any v2.1 failure caused by a bad task?

No. We repeated the audit on all 50 non-perfect v2.1 outputs. Every glossary form is now documented, so the literal-variant test no longer applies. Instead we diffed every output against the key cell by cell, listed the cells that failed the same way in more than one run, and checked each one against the notice and the input files.

Infrastructure and recoveries

  • Infrastructure failures: 9 in v2.1 (2 in v2). All were provider transport failures; none came from the harness.
    • 4 connection failures during the 22:25 outage, all on task 05.
    • 5 dropped Nemotron streams, on tasks 02 (×2), 13 (×2) and 06.
  • Each was retried exactly once, at the user's request, under the same protocol. The primary record is kept, and the retry is logged in infrastructure_retries.json with its own journal.
    • 7 retries scored 100.
    • The 2 task 13 Nemotron retries exhausted the output budget without writing a file.
  • Every condition has a graded result. None of the 192 v2.1 conditions is left as an infrastructure failure.
  • Cost: about $4.43 for v2.1 ($2.27 GLM, $2.16 Nemotron) at approximate list rates, close to v2's $4.41.

Inferences and thoughts

  1. The audit was necessary. Without it, v2 would have reported no workspace effect and a much weaker task 14. The defects were not random noise: they removed signal from specific cells of the design.
  2. Hindi workspaces are the hard part, not Hindi prompts. Reading Devanagari headers, Devanagari digits, Hindi month names and time words costs more than understanding the instruction. This matches the token data: Hindi files enlarge GLM's input by 32% and Nemotron's output by 23%.
  3. The models are close overall but fail differently. GLM almost always writes a file (no missing files in v2.1) and loses on details. When Nemotron writes a file it is more often right: 72 correct of 83 runs with a file. But 13 of its 96 runs ended without one. Budget behaviour matters as much as accuracy for Nemotron.
  4. Per-condition results should not be read individually. A 29% flip rate on identical tasks means a single cell can go either way. The workspace effect holds up because it is a 22 vs 6 imbalance across 96 pairs and appears in most tasks and both models.
  5. If time allows before 22 Nov, a second v2.1 replication would help most. It costs about 8 hours and $4.40, and would let the paper report run-to-run stability instead of a single sample.

Limitations to disclose

  • Synthetic data. Hindi and Hinglish text was written by an AI model with self-review only, not independent human review.
  • The v2.1 notice change came after seeing v2 outcomes (see the disclosure above). No tasks were added, removed or selected on scores.
  • One run per condition, 16 tasks, two models: exploratory, with no significance claims and no claims about Indian languages in general.
  • Approximate cost rates. Budgets: 32,768 tokens per response, 65,536 output and 600,000 input tokens, 40 requests and 1,200 s per attempt.
